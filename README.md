# 컬쳐랜드 써봄 (SSEOBOM)

> 상품권, 어디서 어떻게 쓸까?

**써봄(SSEOBOM)**은 상품권을 어디서 사용할 수 있는지 확인하고, 실제 사용하기까지 필요한 절차를 단계별로 안내하는 상품권 이용정보 서비스입니다. 온라인·오프라인 사용처를 검색하고, 상품권 종류와 사용처에 따른 이용 방법을 쉽게 확인할 수 있습니다. 초기에는 컬쳐랜드상품권·컬쳐캐쉬를 중심으로 제공합니다.

Y-AI 메이커톤 2026 **컬쳐랜드 사전 미션** 제출용 클릭형 시제품입니다. 사용처 확인(어디서)과 상품권 사용 안내(어떻게)를 **하나의 이용 흐름**으로 잇는 컬쳐랜드 **앱** 기능을 제안합니다. 그리고 “누구라도” — 가장 불편한 사람도 가장 편하게 쓸 수 있도록 **저시력·색각 이상 이용자**를 위한 보기 설정을 함께 넣었습니다.

- **클릭형 시제품**: https://usedupnote.github.io/sseobom/
- **설명 자료(PDF, 5쪽)**: [docs/explain.pdf](docs/explain.pdf)

PC에서 열면 왼쪽 패널의 **상황별 시나리오 A~E·M·P·L** 버튼으로 바로 시연할 수 있습니다. 휴대폰에서는 앱 화면이 전체로 열리고, 오른쪽 아래 **시연 시나리오** 버튼을 쓰면 됩니다.

> 컬쳐랜드 공식 서비스가 아닌 대회 제출용 시제품입니다. 결제·충전·계정은 모두 시연용 가상 데이터이며, 브랜드 에셋은 미션 제공 범위에서만 사용했습니다.

## 시연 시나리오

| | 상황 | 시연하는 질문·진입 | 보여주는 것 |
|---|---|---|---|
| A | 매장 계산대에서 지금 바로 쓰고 싶을 때 | “편의점에서 컬쳐랜드상품권 써도 돼?” | 매장 사용 가능 → 충전 없이 문자 바코드로 결제하는 3단계 안내 → 시연용 상품권 문자 → 완료 |
| B | 결제창에 컬쳐캐쉬가 없는 곳에서 쓰고 싶을 때 | “쿠팡에서 쓸 수 있어?” | 결제창에서는 바로 쓸 수 없음 → 쿠팡캐시 전환(수수료 6%, 월 50만원) → 수수료 계산·전환 화면 |
| C | 쓰는 방법이 여러 가지라 고르기 어려울 때 | “CGV” | 온라인 바로사용·매장 바코드·쿠폰을 단계 수와 충전 필요 여부로 비교 |
| D | 이름이 비슷한 다른 상품권을 받았을 때 | “문화상품권 18자리 충전되나요?” | 충전 불가 사유(발행사가 다르고 2023-01-01 제휴 종료)와 대안 |
| E | 공식 목록에 없는 곳을 물었을 때 | “닌텐도”, “배달의민족” | 공식 목록에 없는 곳은 ‘확인 필요’, 결과가 없으면 비슷한 이름·공식 목록·고객센터로 안내 |
| M | 문자로 상품권을 선물받았을 때 | 상품권 문자의 [사용처/잔액안내] 링크 | 링크로 들어오면 ‘내 상품권’이 자동으로 설정됨 |
| P | 받은 상품권이 사진첩에 흩어져 있을 때 | 홈·충전 화면의 [사진에서 한 번에 등록] | 사진첩에서 상품권을 찾아 확인한 것만 한 번에 등록 → “충전한 캐쉬, 어디서 쓸까요?” |
| L | 글자가 작고 흐려 읽기 어려울 때 | 저시력 이용자 보기 설정 | 글자 크게 + 고대비로 A를 ‘한 단계씩 크게 보기’로 진행, 바코드 크게 보여주기 |

## 사진에서 한 번에 등록 (일괄등록)

문자·화면 캡처로 사진첩에 흩어진 컬쳐랜드상품권을 찾아, 이용자가 확인한 것만 한 번에 컬쳐캐쉬로 충전하는 제안 기능입니다. 16자리 번호를 한 장씩 입력하다 틀리는 일을 줄입니다(공식 안내: 20회 이상 잘못 입력하면 하루 동안 충전 제한).

| 단계 | 화면 |
|---|---|
| 1. 안내와 동의 | 무엇을 하는지, 사진을 어떻게 다루는지 먼저 알리고 사진 접근을 묻습니다 |
| 2. 사진첩 살펴보기 | 진행률과 찾은 장수를 보여줍니다 |
| 3. 확인하고 고르기 | 등록 가능(16자리) · 확인 필요(번호를 다 읽지 못함) · 등록 불가(18자리 문화상품권)로 나눠 보여주고, 체크한 것만 등록합니다. 번호는 앞뒤 4자리만 표시하고, 이미 등록한 상품권은 다시 등록되지 않습니다 |
| 4. 등록 완료 | 충전된 금액을 보여주고 “충전한 캐쉬, 어디서 쓸까요?”로 사용처 검색에 연결합니다 |

시제품은 **가상 사진첩**([`data/demo.js`](data/demo.js))으로 흐름만 시연합니다. 실제 사진에는 접근하지 않고, 상품권 번호도 읽거나 받지 않습니다. 실제 적용에는 기기 안 사진 분석(문자 인식), 컬쳐랜드 충전 연동, 사진 접근 동의 절차가 필요합니다. 구현은 [`js/views/bulk.js`](js/views/bulk.js)에 있습니다.

## 누구라도 — 저시력·색각 이상 이용자 대응

시각장애인의 대부분은 시력이 일부 남은 저시력입니다(WHO 2010 추정 약 86%). 화면을 확대하거나 고대비로 보는 이용자도 같은 흐름으로 끝까지 쓸 수 있게 했습니다.

| 유형 | 어려움 | 써봄의 대응 |
|---|---|---|
| 시력저하 | 교정해도 흐릿하게 보임 | **[가] 보기 설정**: 글자 3단계(최대 150%), 최소 13px, **바코드 크게 보여주기**, **읽어주기**(브라우저 내장 음성) |
| 시야장애 | 시야 일부만 보임(양이측 반맹·터널 시야) | **한 단계씩 크게 보기**: 한 화면에 한 단계, 가운데 배치, 큰 이전/다음 |
| 적록 색각 이상 | 빨강과 초록 구분이 어려움 | 판정을 색 + 아이콘 모양(원·둥근 사각·사각·점선) + 글자로, 선택 상태는 체크·밑줄 |
| 전색맹 | 색 없이 명암으로만 보임 | **고대비 테마**(검정·흰·노랑) 글자 대비 7:1 이상, 기기의 고대비 설정 자동 반영 |

검증 결과:
- 글자 대비 미달 7종 → 0. 텍스트 957개를 자동 점검했고, 기준은 기본 4.5:1, 고대비 7:1입니다.
- 13px 미만 글자 178개 → 0. 장식용 아이콘 글자는 제외했습니다.
- 글자를 125%·150%로 키워도 화면이 넘치지 않습니다(29개 화면).
- 흑백·적록 색각 시뮬레이션에서도 상태가 구분되는지 확인했습니다.
- 색각 이상은 국내 법적 시각장애 기준(시력·시야)에는 해당하지 않지만, 같은 원칙으로 함께 대응했습니다.

### 저시력 관점 나란히 보기 (시연용)

PC 시연 페이지 왼쪽 패널의 **‘오른쪽에 저시력 관점 화면 띄우기’**를 체크하면, 조작하는 폰 옆에 같은 화면이 저시력 이용자에게 어떻게 보일지 하나 더 뜹니다. 왼쪽 폰의 화면 이동·스크롤·입력이 오른쪽에 그대로 따라옵니다.

| 설정 | 선택지 |
|---|---|
| 흐림(시력저하) | 없음 · 약하게 · 중간 · 강하게 · 아주 강하게 |
| 시야(시야장애) | 전체 · 양이측 반맹 · 터널 시야 — 마우스 위치가 시선입니다 |
| 색(색각 이상) | 그대로 · 적록 색각 · 전색맹 |

켜 둔 채로 [가] 보기 설정(글자 크게·고대비)이나 시나리오 L을 누르면, 같은 흐림에서도 글자가 얼마나 더 읽히는지 바로 비교할 수 있습니다. 이해를 돕기 위한 시뮬레이션이며, 실제 보이는 모습은 사람마다 다릅니다. 구현은 [`js/lowvision.js`](js/lowvision.js)에 있습니다.

## 화면 흐름

```
앱 홈 검색바 / 문자 상품권 링크 / 충전 완료 화면
  → [입력] 이름·카테고리·자연어 + 내 상품권 선택
  → [결과] “이렇게 이해했어요” 해석 칩 · 판정(바로 가능/바꿔서 가능/불가/확인 필요) · 온라인·매장 구분 · 출처·확인일
  → [안내] 내 상품권 기준 단계(충전 단계 자동 추가·생략) · 수수료 계산 · 방법 비교
  → [앱 화면] 시연용 문자 상품권·충전·바코드 결제·전환·쿠폰·기프트코드 → 안내로 돌아가기

홈·충전 화면의 [사진에서 한 번에 등록]
  → 사진첩 살펴보기 → 찾은 상품권 확인·선택 → 일괄 등록 → “충전한 캐쉬, 어디서 쓸까요?” → [입력]
```

### 다음 동작으로 바로 연결

안내 문구가 다음에 할 일을 가리키면, 말로만 두지 않고 버튼으로 이어 줍니다.

| 안내 | 연결되는 곳 |
|---|---|
| 선물·경품 상품권: “먼저 [교환소]에서 교환해요” | [교환소 열기] → 시연용 교환소 → 충전 또는 원래 화면으로 복귀. 사용 안내에도 교환 단계가 맨 앞에 붙음 |
| 종이 상품권: “공지·고객센터에서 확인” | [공지사항 보기] · [고객센터 1577-2111] |
| 스마트문상: “안내 페이지에서 확인” | [스마트문상 안내 보기] |
| 판정 ‘확인 필요’ | [공식 사용처 목록 보기] · [고객센터 1577-2111] |
| 잔액·환불 안내 | [문자 상품권 열어 보기] · [앱 홈에서 잔액 보기] / [환불 약관 보기] · [고객센터] |
| 전환·바코드 결제에서 잔액 부족 | [충전하기] |
| 충전·교환·일괄등록 완료 | “충전한 캐쉬, 어디서 쓸까요?” 등 다음 화면 |

교환소 화면은 공식 충전 안내의 문구(카카오톡·아이넘버·기프티쇼·이벤트 경품으로 받은 상품권은 교환소에서 상품권으로 교환 후 충전)까지만 담았습니다. 실제 교환소의 입력 항목과 유효기간은 로그인 뒤에만 보여 확인하지 못했고, 화면에도 그렇게 적었습니다.

## 구현 범위

**구현함**
- 홈 진입, 입력, 결과, 목록, 결과 없음, 사용 안내 화면
- 해석 칩 수정, 상품권 판별 도우미(상품권 번호는 받지 않음)
- 사용처 53곳(공식 154곳 중 선정), 이용 방식 7종, 카테고리 8종
- 시연용 앱 화면 8종(교환소·사진 일괄등록 포함), 진행 체크, 즐겨찾기 연동
- 다음 동작 버튼: 안내가 “먼저 교환소에서 교환”, “고객센터에서 확인”처럼 다음 동작을 가리키면 그 화면·공식 페이지·전화로 바로 연결
- 규칙 기반 질문 해석기(초성·오타·조사 처리)와 자동 테스트
- 저시력 대응: [가] 보기 설정(글자 3단계·고대비), 한 단계씩 크게 보기, 바코드 크게 보여주기, 읽어주기

**구현 안 함** (컬쳐랜드 내부 검토·개발 전제)
- 실제 결제·충전·전환·로그인·본인인증
- 실제 바코드 발급, 상품권 번호(PIN) 처리
- 실제 사진첩 접근과 문자 인식(OCR). 일괄등록은 가상 사진첩으로 흐름만 시연
- 공식 사용처 154곳 전체·실시간 연동, LLM 해석
- 위치 기반 매장 찾기, PC 화면(설명 자료에 구상만 제시)
- 실기기 스크린리더(VoiceOver·TalkBack) 검수, 실제 저시력 이용자 사용성 테스트

## 실행 방법

빌드 도구 없는 정적 사이트입니다(HTML·CSS·ES 모듈).

```bash
python tools/serve.py 8650 .
```

브라우저에서 http://localhost:8650 을 엽니다. GitHub Pages에는 저장소를 그대로 배포합니다.

```bash
node tests/parser.test.mjs
```
